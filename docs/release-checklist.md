# Что проверить перед публичным запуском

## Требуется решение владельца
- Подтвердить актуальность телефона, email и Telegram, перенесённых из старого репозитория.
- Подтвердить основной домен и HTTPS. Задать SITE_ORIGIN только для окончательного адреса.
- Утвердить реально предлагаемые услуги, особенно ведение SEO и рекламы. Сейчас это каталог по запросу владельца, а не доказательство наличия команды специалистов.
- При необходимости добавить реальные стартовые цены с чётким составом и сроками. Сейчас числовые цены не выдуманы.
- Подтвердить право показывать демопроекты. Статусы «демонстрационный» и «концепция» не убирать без оснований.
- Выбрать режим обращения: прямые контакты/почтовый черновик уже работают как UI; автоматическая отправка требует настоящих серверных настроек и подготовленных условий обработки данных.
- После настройки провести одну согласованную реальную отправку, проверить получение и ответы. Автоматические тесты этого не делают.

## Проверить на конечном хостинге
- Правильная папка публикации — содержимое dist/.
- Домен, HTTPS, переадресации и работа внутренних маршрутов.
- Реальный номер и почта открываются на телефоне пользователя.
- При серверной форме работают PHP и исходящий HTTPS; секреты находятся вне публичных файлов.
- canonical/sitemap содержат основной адрес; preview не индексируется.
- Страница 404 подключает корректный корневой путь, особенно на GitHub Pages в подкаталоге.
- Если подключаются аналитика/реклама, отдельно проверить их настройки и необходимые сведения посетителям.

Не публиковать утверждения «без ошибок», «гарантированные продажи» или «юридически полностью готов» на основании прохождения тестов.
